## 0. Що таке Git і GitHub і навіщо вони

**Git** — програма на твоєму комп’ютері, яка запам’ятовує історію змін у файлах.
Уяви збереження в грі: кожного разу, коли ти робиш «збереження» (commit),
Git фотографує стан усіх файлів. Потім можна повернутися до будь-якого моменту,
подивитися, хто й що змінив, і чому.

**GitHub** — сайт, де зберігаються Git-репозиторії. Це як Google Drive для коду,
але з історією змін, обговореннями й інструментами для спільної роботи.

| | Git | GitHub |
|---|---|---|
| Де живе | на твоєму комп’ютері | в інтернеті |
| Що робить | зберігає історію змін | зберігає репозиторії, дає працювати разом |
| Чи потрібен інтернет | ні | так |

**Навіщо це все:**

- **Не губити роботу.** Більше ніяких `сайт_фінал_точно_фінал_2.html`.
- **Працювати разом.** Десять людей можуть редагувати один проєкт і не затирати одне одного.
- **Бачити, хто, що і навіщо змінив.** Кожна зміна підписана й має пояснення.
- **Безпечно експериментувати.** Гілки дозволяють пробувати ідеї, не ламаючи основну версію.
- **Портфоліо.** Твій профіль на GitHub — це резюме, яке бачать роботодавці.

### Кілька слів, які варто знати

| Слово | Що означає |
|---|---|
| **Репозиторій (repo)** | Папка проєкту разом з усією історією змін |
| **Commit** | Збереження: знімок файлів + повідомлення про те, що змінено |
| **Branch (гілка)** | Паралельна версія проєкту для експериментів |
| **`main`** | Головна гілка, «офіційна» версія |
| **Remote** | Копія репозиторію на сервері (наприклад, на GitHub) |
| **Fork** | Твоя власна копія чужого репозиторію на GitHub |
| **Clone** | Завантаження репозиторію з GitHub на комп’ютер |
| **Push** | Відправити свої коміти на GitHub |
| **Pull** | Забрати нові коміти з GitHub собі |
| **Pull Request (PR)** | Пропозиція: «ось мої зміни, додайте їх, будь ласка» |

### Як рухаються зміни

```
 Твій комп’ютер                                     GitHub
┌───────────────────────────────────────┐        ┌──────────────┐
│ робоча папка → staging → репозиторій  │ push → │  твій fork   │ ── Pull Request ──► оригінал
│  (редагуєш)   (git add) (git commit)  │ ← pull │              │
└───────────────────────────────────────┘        └──────────────┘
```

Три місця на твоєму комп’ютері:

1. **Робоча папка** — файли, які ти бачиш і редагуєш.
2. **Staging (індекс)** — «кошик» змін, які ти хочеш зберегти в наступному коміті. Туди їх кладе `git add`.
3. **Репозиторій** — збережена історія. Туди зміни потрапляють після `git commit`.

## 1. Підготовка

### 1.1. Акаунт на GitHub

Зареєструйся на [github.com](https://github.com), якщо ще не маєш акаунта.

### 1.2. Встанови Git

- **Windows:** завантаж з [git-scm.com](https://git-scm.com/download/win) і встанови з налаштуваннями за замовчуванням. Разом з ним встановиться **Git Bash** — термінал, у якому ми працюватимемо.
- **macOS:** відкрий Terminal і введи `git --version`. Якщо Git не встановлений, система сама запропонує встановити його.
- **Linux:** `sudo apt install git` (Ubuntu/Debian) або аналог для твого дистрибутива.

Перевір, що все працює:

```bash
git --version
```

Маєш побачити щось на кшталт `git version 2.47.0`.

### 1.3. Познайомся з Git

Git підписує кожен коміт твоїм ім’ям і поштою. Вкажи ту саму пошту, що й на GitHub:

```bash
git config --global user.name "Твоє Ім’я"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

Перевір:

```bash
git config --list
```

### 1.4. Редактор коду

Підійде будь-який, але ми радимо [VS Code](https://code.visualstudio.com/). У ньому є вбудований термінал (меню **Terminal → New Terminal**).

## 2. Fork: своя копія репозиторію

Цей репозиторій належить організатору воркшопу, тож напряму змінювати його ти не можеш.
Тому спершу зробимо **fork** — твою особисту копію на GitHub.

1. Відкрий сторінку цього репозиторію на GitHub.
2. Натисни кнопку **Fork** у правому верхньому куті.
3. Натисни **Create fork**.

Тепер у тебе є `github.com/ТВІЙ-НІК/maine-coon-workshop`. Це твій простір, тут можна все.

---

## 3. Clone: завантаж репозиторій на комп’ютер

1. На сторінці **свого fork** натисни зелену кнопку **Code** і скопіюй HTTPS-адресу.
2. У терміналі перейди туди, де хочеш тримати проєкт, і виконай:

```bash
git clone https://github.com/ТВІЙ-НІК/maine-coon-workshop.git
cd maine-coon-workshop
```

`git clone` завантажує всі файли **разом з усією історією**.
`cd` (change directory) — переходить у папку проєкту.

Відкрий файл `index.html` у браузері (просто двічі клацни на ньому). Ось наш сайт!

Подивись, що Git знає про цю папку:

```bash
git status
```

Побачиш `nothing to commit, working tree clean` — все чисто, змін немає.

> 💡 **`git status` — твоя найкраща подруга.** Виконуй її щоразу, коли не впевнений(а), що відбувається.

## 4. Перший commit

### 4.1. Зміни файл

Відкрий `index.html` у редакторі. Знайди коментар `ЗАВДАННЯ 1` і зміни заголовок під ним на свій. Наприклад:

```html
<h1>Пухнастий велетень з лісу</h1>
```

Збережи файл і онови сторінку в браузері — заголовок змінився.

### 4.2. Подивись, що змінилося

```bash
git status
```

Git бачить, що `index.html` змінено (`modified`), але ще не збережено в історії.

А тепер подивись **що саме** змінилося:

```bash
git diff
```

Рядки з `-` видалено, з `+` додано. Щоб вийти з перегляду, натисни `q`.

### 4.3. Поклади зміни в staging

```bash
git add index.html
```

Ще раз `git status` — тепер файл зелений, у розділі `Changes to be committed`.

> Щоб додати одразу всі змінені файли, є `git add .` (крапка = «все в цій папці»).

### 4.4. Зроби commit

```bash
git commit -m "Змінив заголовок на головній"
```

Прапорець `-m` — це повідомлення коміту. Пиши його так, щоб через місяць було зрозуміло, **що** і **навіщо** ти зробив(ла).

| Погано | Добре |
|---|---|
| `fix` | `Виправив опечатку в описі породи` |
| `зміни` | `Додав факт про вагу мейн-кунів` |
| `asdf` | `Збільшив шрифт заголовка на мобільних` |

Вітаю, це твій перший коміт! 🎉

## 5. Історія змін

```bash
git log
```

Ти побачиш список комітів: хто, коли, з яким повідомленням. Найновіший — зверху. Вихід — `q`.

Компактніший варіант:

```bash
git log --oneline
```

Кожен коміт має унікальний ідентифікатор (хеш) — наприклад, `a1b2c3d`. Подивитися, що змінив конкретний коміт:

```bash
git show a1b2c3d
```

## 6. Push: відправ зміни на GitHub

Поки що твій коміт існує лише на комп’ютері. Відправмо його на GitHub:

```bash
git push
```

Під час першого push Git попросить увійти в GitHub. На Windows і macOS зазвичай відкривається вікно браузера — просто підтвердь вхід.

> **Пароль не підходить?** GitHub не приймає звичайний пароль у терміналі. Варіанти:
> встанови [GitHub CLI](https://cli.github.com/) і виконай `gh auth login`,
> або створи Personal Access Token (Settings → Developer settings → Personal access tokens) і встав його замість пароля.

Онови сторінку свого fork на GitHub — твій новий заголовок уже там, і в історії комітів видно твоє повідомлення.

## 7. Гілка і свій кіт

Тепер головне завдання: **додати свого кота на спільний сайт**.

Серйозні зміни роблять не прямо в `main`, а в окремій **гілці**. Так `main` завжди лишається робочою, а ти можеш спокійно експериментувати.

### 7.1. Створи гілку

```bash
git switch -c add-cat-ТВІЙ-НІК
```

`-c` означає «створи нову». Перевір, на якій гілці ти зараз:

```bash
git branch
```

Поточна гілка позначена зірочкою `*`.

> У старих інструкціях можна зустріти `git checkout -b назва` — це те саме, просто старіший спосіб.

### 7.2. Додай кота

Відкрий `data/cats.js`. Скопіюй один блок `{ … }` і встав його **в кінець списку**, перед `];`. Зміни значення:

```js
  {
    name: "Мурчик",
    github: "твій-нік",
    fur: "#6B6B6B",
    stripe: "#2B2B2B",
    fact: "Мейн-кун — офіційний кіт штату Мен з 1985 року."
  },
```

Онови `index.html` у браузері. Твоя картка з’явилася внизу сторінки? Чудово!
Нічого не з’явилося? Найчастіше причина — пропущена кома або лапка.

### 7.3. Commit і push гілки

```bash
git status
git add data/cats.js
git commit -m "Додав кота Мурчика"
git push -u origin add-cat-ТВІЙ-НІК
```

`-u origin назва-гілки` пояснює Git, куди відправляти цю нову гілку. Наступного разу для неї вистачить просто `git push`.

## 8. Pull Request

Pull Request — це спосіб сказати: «Я зробив(ла) зміни у своїй копії. Будь ласка, перегляньте їх і додайте в оригінальний проєкт».

1. Відкрий свій fork на GitHub. Зверху з’явиться жовта плашка **Compare & pull request** — натисни її.
2. Переконайся, що зміни йдуть **з твоєї гілки** у **`main` оригінального репозиторію**.
3. Напиши назву (наприклад, `Додав кота Мурчика`) і заповни короткий опис.
4. Натисни **Create pull request**.

Далі організатор переглядає PR: може залишити коментар, попросити щось виправити або одразу натиснути **Merge**. Якщо попросять зміни — просто зроби новий коміт у тій самій гілці й `git push`, PR оновиться сам.

**Саме так працює весь open source:** від маленьких проєктів до Linux і VS Code.

## 9. Pull: забери чужі зміни

Поки ти працював(ла), інші учасники теж додали котів. Твоя локальна копія про це не знає. Підтягнімо зміни з оригінального репозиторію.

### 9.1. Підключи оригінал як `upstream` (один раз)

```bash
git remote add upstream https://github.com/ОРГАНІЗАТОР/maine-coon-workshop.git
git remote -v
```

Тепер у тебе два remote:
- `origin` — твій fork;
- `upstream` — оригінальний репозиторій.

### 9.2. Онови свій `main`

```bash
git switch main
git pull upstream main
git push
```

`git pull` = завантажити нові коміти + влити їх у поточну гілку.
Останній `git push` оновлює твій fork на GitHub.

Відкрий `index.html` — тепер там коти всіх учасників, чий PR уже прийняли.

> Альтернатива без терміналу: на сторінці свого fork на GitHub натисни **Sync fork → Update branch**, а потім зроби `git pull` у себе.

## 10. Конфлікт (і чому це не страшно)

Конфлікт виникає, коли дві зміни зачіпають **той самий рядок**, і Git не може сам вирішити, яку лишити. Тоді він питає тебе. Давай влаштуємо конфлікт навмисно.

### 10.1. Зміна в гілці

```bash
git switch -c new-lead
```

У `index.html` зміни текст абзацу з класом `hero__lead` (одразу під заголовком) на будь-який інший.

```bash
git commit -am "Новий опис у шапці"
```

> `-a` автоматично додає всі змінені відстежувані файли, тож окремий `git add` не потрібен.

### 10.2. Інша зміна того самого рядка в `main`

```bash
git switch main
```

Зміни **той самий** абзац, але на інший текст.

```bash
git commit -am "Інший опис у шапці"
```

### 10.3. Злиття

```bash
git merge new-lead
```

Git повідомить: `CONFLICT (content): Merge conflict in index.html`. Відкрий файл:

```
<<<<<<< HEAD
        Текст, який ти написав(ла) в main
=======
        Текст, який ти написав(ла) в гілці new-lead
>>>>>>> new-lead
```

- Між `<<<<<<<` і `=======` — версія з поточної гілки (`main`).
- Між `=======` і `>>>>>>>` — версія з гілки, яку зливаєш.

Залиш той текст, який хочеш (або поєднай обидва), і **видали всі три рядки-маркери**. Потім:

```bash
git add index.html
git commit -m "Злив гілку new-lead, вирішив конфлікт"
```

Готово. Конфлікт — не помилка, а просто питання від Git: «Ви двоє змінили одне й те саме, що лишаємо?»

> У VS Code над конфліктом з’являються кнопки **Accept Current / Accept Incoming / Accept Both** — так ще простіше.

## 11. Бонус: опублікуй сайт на GitHub Pages

GitHub може безкоштовно розмістити твій сайт в інтернеті.

1. Відкрий свій fork → **Settings → Pages**.
2. У розділі **Build and deployment** вибери **Source: Deploy from a branch**.
3. Гілка: `main`, папка: `/ (root)`. Натисни **Save**.
4. Зачекай 1–2 хвилини й онови сторінку — з’явиться посилання на кшталт `https://ТВІЙ-НІК.github.io/maine-coon-workshop/`.

Тепер кожен `git push` у `main` автоматично оновлює сайт. Поділися посиланням з друзями!
